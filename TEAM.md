# Команда: роли, зоны ответственности, процесс

Три человека, у каждого свой Claude-агент и свой промпт. Главное правило: **у каждого свои файлы**. В чужие файлы не лезем — пишем запрос (§5).

## 1. Роли

| Роль | Чем занимается | Промпт агента | Последнее слово |
|---|---|---|---|
| **Геймдизайнер** | Логика и правила игры: баланс, экономика, цены, классы, ачивки, контракты, задания, тексты, звук; плейтесты; магазин и страница игры в Roblox | `DESIGN_PROMPT.md` | Как игра **играется** и сколько что **стоит** |
| **Художник** | 3D-модели, текстуры, скины, анимации, иконки, иконка и превью игры | `ASSETS_PROMPT.md` | Как игра **выглядит** |
| **Разработчик** (интегратор) | Код, сборка мира в Studio, подключение моделей и конфигов, производительность, сохранения, публикация | `AGENT_PROMPT.md` | Как игра **работает** технически |

Если роли не договорились — решает **владелец проекта** (владелец группы Roblox).

## 2. Как роли стыкуются

```
Геймдизайнер ──(JSON-конфиги, тексты, спеки)──┐
                                              ├──► Разработчик ──► игра в Roblox ──► плейтест всех троих
Художник ─────(.rbxm модели, иконки)──────────┘                                         │
     ▲                                                                                  │
     └──────────────────── правки и запросы через Issues ◄──────────────────────────────┘
```

- **Геймдизайнер и Художник работают на одну фазу впереди Разработчика.** Когда Разработчик начинает фазу N, цифры и модели для неё уже готовы или в работе.
- Если модели ещё нет, Разработчик ставит серую заглушку с теми же именами (контракт в `ASSETS_PROMPT.md` §6), потом меняет без правки кода.
- Если цифр ещё нет, Разработчик ставит временные значения в JSON и пометку `"TODO_DESIGN"`. Геймдизайнер их заменяет.

## 3. Кто владеет какими файлами

| Путь | Владелец | Что там |
|---|---|---|
| `Gameplay_Design.md`, `design/` | Геймдизайнер | GDD, подробные спеки, плейтест-отчёты, журнал изменений баланса |
| `src/shared/config/*.json` | Геймдизайнер (**значения**) / Разработчик (**структура**) | Все числа игры. Rojo превращает JSON в ModuleScript. Поля описаны в `docs/config.md` |
| `src/shared/localization/*.csv` | Геймдизайнер | Все тексты для игроков (EN + RU), Rojo превращает в LocalizationTable |
| `assets/` | Художник | Модели `.rbxm`, исходники, иконки, трекер `ASSETS.md` |
| `src/` (кроме config и localization), `places/`, `tools/`, `tests/`, `docs/` | Разработчик | Код, сборка, генераторы мира, тесты, документация по коду |
| `ASSETS_PROMPT.md` §6 (контракт моделей) | Художник + Разработчик | Меняется только по согласию обоих |
| `TEAM.md`, промпты агентов | Все | Меняются по согласию всех |

В GitHub заведи файл `.github/CODEOWNERS` по этой таблице: тогда правка чужих файлов без одобрения владельца не пройдёт.

## 4. Инструменты команды

- **GitHub:** один репозиторий. Ветки `design/...`, `art/...`, `dev/...` → Pull Request в `main`. Сливает **Разработчик** после проверки (`selene`, тесты, запуск в Studio).
- **GitHub Projects** (доска): колонки *Бэклог → В работе → На проверке → Готово*, метки `дизайн`, `арт`, `разработка`, `баг`, `запрос`.
- **Группа (Community) Roblox** с ролями:

| Роль в группе | Кто | Права |
|---|---|---|
| Владелец | Владелец проекта | Всё, выплаты |
| Разработчик | Разработчик | Редактировать и публиковать плейсы |
| Художник | Художник | Загружать ассеты (меши, текстуры, изображения, аудио) |
| Геймдизайнер | Геймдизайнер | Создавать и менять Game Passes, Developer Products, бейджи; видеть аналитику |

- **Плейсы:** основной (публикует только Разработчик), тестовый плейс Художника (проверка моделей), публичная dev-версия для плейтестов.
- **Доход:** договоритесь о долях заранее и запишите их. Выплаты делаются из группы.

## 5. Запросы между ролями

Нужна правка в чужой зоне → **Issue** с меткой `запрос` и меткой роли-адресата. Агенты умеют делать это через `gh issue create`.

Шаблон запроса:
```
Что нужно: <одно предложение>
Зачем: <какая фаза или механика блокируется>
Срок: <к какой фазе>
Детали: <имена частей, поля конфига, скриншот>
```

Шаблон бага:
```
Что: <коротко>
Шаги: 1… 2… 3…
Ожидалось: …
Получилось: …
Устройство: ПК / телефон (модель)
Скриншот или видео: …
```

## 6. Ритм работы

| Когда | Что | Кто |
|---|---|---|
| Понедельник, 30 мин | Планёрка: текущая фаза, кто что делает на неделе, что блокирует | Все |
| 1–2 раза в неделю | **Совместный плейтест** dev-версии (игра кооперативная, тестировать нужно вдвоём-втроём, минимум один с телефона). Геймдизайнер ведёт и пишет отчёт в `design/playtests/ГГГГ-ММ-ДД.md` | Все |
| Конец фазы | Демо: Разработчик показывает критерий готовности фазы, все подтверждают | Все |
| Постоянно | Запросы и баги — Issues, а не личка | Все |

## 8. Что считается «готово»

- **Геймдизайнер:** спека в `design/`, числа в JSON проходят валидацию, тексты в CSV на обоих языках, запись в `design/CHANGELOG.md`.
- **Художник:** ассет в бюджете, по контракту, скриншот в Studio, `.rbxm` в `assets/rbxm/`, строка `ready` в `assets/ASSETS.md`.
- **Разработчик:** критерий фазы выполнен, линтеры и тесты зелёные, консоль чистая, все трое подтвердили на плейтесте.
